Still not sure? Watch this webinar to understand Frappe Cloud pricing in detail and find the right plan for your use case. Frequently asked questions How should I choose the right plan? An ideal hosting configuration is a function of your infrastructure preferences, workload criticality, and risk appetite. Its is also a performance to cost trade-off. Here are some rules of thumb to help you navigate it. If availability and durability guarantees are important, choose AWS or OCI. If costs matter more than guarantees, choose Hetzner. Unified servers suffice for most workloads. If you are willing to pay the premium for App - Database isolation (which helps in case of load spikes on either side), Separate servers are ideal. Shared instances may introduce noisy neighbour problems, and are suitable only for non-critical or experimental workloads. For most production workloads, Dedicated instances are recommended. Having said that, there is no right answer in most cases. Start with the best possible estimate and upgrade to larger plans later as your requirements grow. (Note: Plan downgrades may be subject to constraints offered by the cloud provider.) When should one choose “Shared” vs “Dedicated” instances? Dedicated instances provide reserved compute resources. That offers predictable performance, although at a higher price. Shared instances are a lower-cost alternative where computing power is shared at the infrastructure level. Sharing keeps prices low, but performance can vary depending on overall system load. They’re best suited for development, testing, and other non-critical workloads where occasional slowdowns are acceptable. What is Product Warranty? Product Warranty is support from Frappe engineers for fixing bugs in Frappe Apps (e.g. ERPNext, Frappe HR, Frappe Framework) and Frappe Cloud. When should one choose “Unified server” plans vs “Separate servers” plans? A Unified server runs both the application and database on the same machine. It’s simpler and more cost-effective, and is commonly used for development, testing, and lighter workloads. On the other hand, in the “Separate servers” option, the application and database run on different servers. That provides better isolation and more headroom, which makes it better suited for heavier and more variable workloads. Is Hetzner meant for production workloads? Hetzner is best suited for development, testing, and demo environments. However, it can also be used for production workloads as long as there are no mission-critical use cases (which necessitate reliability guarantees from AWS/OCI). For such workloads (where uptime and durability are critical), Frappe recommends dedicated AWS or OCI instances. Can I start with Hetzner and move to AWS/OCI later? Yes. Many teams start with developer-friendly setups and later move to higher reliability infrastructure as requirements grow. You can start with Hetzner and migrate to AWS / OCI later. However, the type of servers chosen (Unified or App-Db pair) should remain the same, failing which migration can pose challenges. Will performance be slower on Hetzner? It can be. When you choose Hetzner, you prioritise affordability over consistent performance. For most development, demo, and testing use cases, Hetzner works well. If you need predictable performance for sustained workloads, choosing a dedicated instance setup on AWS or OCI is recommended. Can I start small and upgrade later? Yes. You can scale up to larger plans as your requirements grow. However, certain architectural choices (such as Unified vs Separate App–DB) may need to remain consistent to avoid migration complexity.
