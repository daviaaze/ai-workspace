Contribute to Frappe Contents Welcome Home Products Partners Customers Blog Contact About Story Culture Team Values Vision Resources Events Community Testimonials Incubator Careers Push your code Contribute to Frappe We aspire to build great products and services, empower and educate, and be a democratically run organization. 1 Set up your development environment To begin contributing, install Frappe Framework locally and let your curiosity guide you. The best contributions often come from scratching your own itch. Follow the official Frappe Framework installation guide . This guide walks you through installing Bench, creating a site, and running Frappe in developer mode. Take your time here to explore the interface. A clean setup makes everything else smoother. 2 Explore the product like a user Every small or big contribution to Frappe begins the same way: by becoming a user first. Once your environment is ready, spend some time inside the codebase. Run ERPNext locally, try out features, notice friction points and read error logs. Look closely: Could this validation message be clearer? Is this process missing something? Is there a bug here? When something feels improvable, you’ve likely found your first contribution. 3 Find an issue to work on Now that you're familiar with the system and have begun noticing patterns, head to GitHub and look for open issues: Frappe Framework ERPNext Before you begin, make sure to read the contribution guidelines to understand the standards and process. If you’re planning a major change, discuss it with the maintainers first before sending a PR 4 Build your solution Once you’ve chosen your issue, it’s time to build a solution. Fork the repository to your GitHub account, create a new branch, and begin implementing your fix or feature. As you code, follow the existing patterns in the codebase. If your change affects functionality, add tests. If it affects users, update documentation. Write code as if someone will read, extend, and maintain it, because they will. 5 Open a clear pull request When you’re ready, open a Pull Request with a clear explanation of: What you changed Why you changed it How to test it Screenshots (if UI is involved) 6 Respond to review and improve your PR Once you open your Pull Request, a maintainer will review it. This usually means they may: Leave comments on specific lines of code Ask clarifying questions Suggest changes in logic or structure Request tests or documentation updates Almost every PR, even from experienced contributors, goes through revisions. This lets you understand the architecture more deeply . Many long-term contributors built their expertise through these back-and-forth reviews. Not every contribution finds success. Sometimes a PR may be rejected if they don’t meet certain quality bar or project goals. In contrast, if your requested changes are addressed and the maintainer approves your PR, it will soon be merged. Your code contribution becomes part of Frappe and visible to thousands and runs in real projects. That is exactly when your name appears in the project history. Hurray!
